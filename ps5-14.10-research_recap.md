# Technical Recap: PS5 Firmware 14.10 Security Research

## Executive Summary
This document summarizes the research status, findings, and architectural constraints documented in the `ZigZagBoi1/PS5-14.10-Research` repository. The project analyzes userland attack surfaces, syscall behavior, and WebKit vectors on PlayStation 5 firmware version 14.10. 

* **Primary Status:** No kernel read/write or complete exploit chain is demonstrated. 
* **Key Finding:** The Lua userland loader attack surface (via system calls and ioctl probes) has been thoroughly analyzed without disclosing kernel pointers or yielding KASLR bypasses directly through syscall channels.
* **Active Vector:** Research has pivoted primarily to WebKit heap manipulation and memory layout analysis.

---

## 1. Entry Vectors & Environments

### Vector 1: Lua 5.1 Userland Loader
* **Mechanism:** Triggered via save file manipulation in *Hamidashi Creative* (Artemis / Lua engine).
* **Network Interface:** Spawns a TCP listener on port `9026` to accept Lua probe scripts.
* **Userland Capabilities:**
  * Direct userland memory access via custom `memory` API.
  * Syscall invocation via `make_syscall(N)` (bypasses Lua filter wrappers, though kernel permissions still apply).
  * Arbitrary userland function invocation (`native.fcall_with_rax`).
  * Thread allocation via `thr_create` (syscall 430) and `thr_new` (syscall 455).
  * GPU memory mapping via `dmem0` (`mmap` allocation of 256+ pages for large userland heap space).
* **Constraints:**
  * Process isolation: Fresh userland process / ASLR per TCP connection.
  * Direct physical memory mapping (`dmem0`) is restricted to the GPU direct memory pool (`0x100000000` - `0x150000000`).
  * Executable space ($X$) cannot be written to ($W^X$ enforcement). Attempting to read or execute protected pages results in immediate process termination.

### Vector 2: WebKit Engine
* **Engine Specs:** WebKit 605.1.15 / Safari 17.0 equivalent (JIT disabled, running LLInt/Low-Level Interpreter only).
* **Heap Architecture:** Standard `x86_64` configuration with Gigacage and IsoHeap disabled.
* **Active Research Targets:**
  * **FontFaceSet UAF (CVE-2026-43715 variant):** Memory corruption vector where specific array buffer reclaims reveal heap pointers. Verified cross-firmware behavior on FW 14.00 and FW 14.10.
  * **Canvas Same-Type Aliasing (CVE-2026-43720):** Reclaim primitive under investigation for bidirectional userland heap read/write.
  * **localStorage Bridge:** Cross-page IPC channel for maintaining persistent userland state across browser navigations.

## 2. Attack Surface Analysis & Findings

| Surface / Mechanism | Probed Scenarios | Result / Current Status |
| :--- | :--- | :--- |
| **Syscall KASLR Leaks** | 17+ FreeBSD/Sony leak techniques across ~400 syscalls | **Exhausted.** Zero kernel pointers disclosed via standard or custom syscall interfaces. |
| **Device Drivers (`/dev`)** | 34 accessible `/dev` nodes via `ioctl` (syscall 54) | **Restricted.** Sony employs NID-hash command codes instead of standard FreeBSD `_IOC` encoding. NID mappings from prior firmwares (e.g., 13.60) do not match 14.10. |
| **Fault Oracle** | KASLR base determination via memory access faults | Can detect image base presence per boot via side-channel fault timing/responses, but does not grant direct pointer read/write. |
| **WebKit Heap Leak** | `FontFace` lifecycle manipulation | Confirmed 192-byte `ArrayBuffer` reclaim exposes live heap pointers at offsets `+0x58` and `+0x68`. |

## 3. Testing & Verification Tooling

* **Offline Verification Suite:** `python3 tools/verify_offline.py`
  * Standard-library Python 3.10+ verifier designed to validate probe framing, ABI formatting, and output parsers against local fixtures without requiring real hardware.
* **Probe Delivery Tooling:** `tools/send_probe.py` / `tools/send_probe.ps1`
  * Transmits Lua payload scripts to the TCP target (`port 9026`) and logs raw console responses.

---

## 4. Guidance for Automated Agents

When generating analysis or new probe logic for this repository context, adhere to the following rules:

1. **Lua 5.1 Syntax Limitations:** 
   * Standard Lua 5.1 numbers are double-precision floats; all 64-bit address manipulations must use the repository's native `uint64()` object wrappers.
   * Avoid unsupported formatting specifiers (e.g., `%b`).
2. **Safety & Exception Handling:**
   * Wrap all experimental userland memory access or syscall invocations inside `pcall()` blocks.
   * Do not hardcode memory addresses across runs due to per-connection ASLR.
3. **Execution Safety:**
   * Never attempt to read XO (Execute-Only) memory pages; doing so bypasses standard exception handlers and terminates the userland process immediately.
4. **Evidence Standards:**
   * Non-zero buffer returns or Lua runtime errors do not constitute kernel pointer leaks or kernel panics. Explicit address verification against baseline layout tables is required.
